# ADR 0001: Работа с файлами ai-challenge-app через чат CRM

## Статус и контекст

Принято. Project Desk уже предоставляет чат по знаниям `ai-challenge-app` через
RAG и DeepSeek. Для задач вроде поиска использований API и обновления документации
ассистенту также нужен доступ к текущим файлам и возможность выбирать следующие
операции по результатам предыдущих.

## Решение

Использовать существующий `POST /api/chat` и интерфейс переписки. CRM остаётся
интерфейсом поддержки; файловый каталог и RAG относятся к `ai-challenge-app`.
Обёртка Project MCP по умолчанию выбирает каталог из `--project-root`.
`SUPPORT_FILES_ROOT` позволяет указать другой checkout этого проекта.

После `project_get_info` сервис включает цикл инструментальных действий, если
сервер сообщает `fileToolsVersion >= 1`. Модель возвращает JSON с `toolCalls`
либо финальными `claims`. Сервис вызывает разрешённые MCP-инструменты, передаёт
их фактические результаты модели и проверяет точные цитаты финального ответа.
При старом Project MCP сохраняется прежний путь RAG и прямого чтения документов.

| Инструмент | Назначение |
|---|---|
| `project_list_files` | Список публичных файлов с пагинацией |
| `project_search_files` | Поиск буквальной строки по текущим файлам, пути и строки |
| `project_read_file` | Диапазон строк и SHA256 всего файла |
| `project_write_file` | Сохранение Markdown-документа с фактическим diff |
| `project_preview_diff` | Проверка и diff без записи |

Файловые инструменты не зависят от RAG. Реализация сервера и её тесты поставляются
в интеграционном патче для `ai-challenge-app`; сама CRM собирается независимо.

## Ограничения и последствия

- IO ограничен корнем проекта через `os.Root`. Скрытые и приватные каталоги,
  `.env`, `.local`, сборки и символьные ссылки исключены из файлового корпуса.
- Чтение доступно для разрешённых UTF-8 исходников и документов до 512 КиБ,
  включая большой файл агента. Один ответ чтения ограничен диапазоном строк
  и 32 КиБ. Пагинация и пропущенные при поиске файлы помечаются явно.
- Запись ограничена `README.md`, `CHANGELOG.md` и `.md` внутри `docs/`, до 32 КиБ.
  Модель не получает выполнения команд или инструментов изменения CRM.
- Перед подготовкой изменения нужны чтения двух разных файлов. Замена существующего
  документа требует полного чтения в текущем запросе и совпадения SHA256.
  Конфликт возвращается как `file_conflict`; модель должна перечитать документ.
- Сохранение использует временный файл и переименование. Одинаковое содержимое
  не переписывается и возвращает пустой diff.
- Один вопрос ограничен 12 шагами модели, 30 операциями, четырьмя сохранениями
  и 300 секундами. Файлы и результаты инструментов передаются внешнему DeepSeek
  для выполнения запроса пользователя.
- Журнал MCP формируется клиентом по фактическим вызовам. Результаты сохранений
  и diff добавляются сервисом к тексту ответа даже при ошибке последующей генерации.
  В обращении ответ и журнал сохраняются в SQLite; общий чат остаётся во вкладке.
- Изменение индексируемых документов требует штатной переиндексации RAG.
  До неё файловые инструменты продолжают читать актуальные файлы напрямую.

## Проверка

`scripts/check_file_assistant.py` выполняет два запроса через обычный чат:
поиск обработки `/help` и создание либо обновление
`ai-challenge-app/docs/demo/file-assistant-context.md` по реализации Sliding Window.
Проверяются рабочий каталог, чтение минимум трёх файлов, источники и diff.
Повторный запуск обрабатывает существующий документ.

Обычные Go-тесты используют временную CRM и подставную модель. Дополнительный
`TestFileAssistantEndToEnd` при заданном `PROJECT_FILES_TEST_BINARY` проверяет
полный путь HTTP → протокол модели → настоящий MCP → временные файлы,
создание документа и повторное сохранение без изменений.
